Technical implementation sheet / full v1 path / prototype-first gate / 2026-07-26

1. Build Target

Build Rivu as a Go CLI/TUI project filesystem control deck. The registry is operational truth, the filesystem is discovery, and every TUI action must have a CLI-equivalent behavior path.

9. TDD Loop

  1. Pick one public CLI seam.
  2. Create temp RIVU_HOME and workspace fixture.
  3. Write one failing behavior test.
  4. Implement minimum code.
  5. Run targeted test, then go test ./....

10. Safety Gates

  • No delete command.
  • Dry-run before Source writes, Flow, Delta, rename.
  • Protected Bank docs are not overwritten silently.
  • Bridge-owned git init locks Rivu git init.

11. Prototype Cut

rivu init --root D:/Projects
rivu scan
rivu list
rivu tui

Everything after this is blocked until the first loop works end to end.

12. Immediate Implementation Order

1. go mod init github.com/bl4nkslate/rivu
2. add cmd/rivu/main.go
3. add internal/cli root command with init/list placeholders
4. add config defaults and RIVU_HOME test override
5. write CLI test for `rivu init --root`
6. implement config write and DB path creation
7. add SQLite migration and registry repository
8. write scan/list CLI tests with temp marker dirs
9. implement scanner and project upsert
10. add minimal Bubble Tea list model after CLI prototype passes

This order keeps the first proof thin: no Source wizard, no Map generator, no dashboard until the registry-backed list exists.
